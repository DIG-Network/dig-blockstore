## Summary

`get_blocks_in_range(&self, start_height: u64, end_height: u64) -> Result<Vec<L2Block>>` retrieves canonical blocks in a height range with inclusive bounds on both ends. Returns blocks in ascending height order.

---

## Specification

```rust
/// Retrieves canonical blocks in a height range [start, end] inclusive.
/// Returns blocks in height order.
pub fn get_blocks_in_range(
    &self,
    start_height: u64,
    end_height: u64,
) -> Result<Vec<L2Block>> {
    if start_height > end_height {
        return Ok(Vec::new());
    }

    let mut blocks = Vec::with_capacity((end_height - start_height + 1) as usize);
    for height in start_height..=end_height {
        if let Some(block) = self.get_block_by_height(height)? {
            blocks.push(block);
        }
    }
    Ok(blocks)
}
```

### Semantics

- **Inclusive range**: Both `start_height` and `end_height` are included.
- **Empty range**: If `start_height > end_height`, returns an empty `Vec` (not an error).
- **Missing heights**: Heights with no canonical entry are silently skipped.
- **Height validation**: Heights beyond the current tip simply have no canonical entry and are skipped.
- **Order**: Blocks are returned in ascending height order.

---

## Acceptance Criteria

- [ ] Returns blocks in `[start_height, end_height]` inclusive
- [ ] Returns blocks in ascending height order
- [ ] Returns empty vec when `start_height > end_height`
- [ ] Skips heights with no canonical entry
- [ ] Heights beyond tip are handled gracefully (no error)
- [ ] Each block is fully deserialized and decompressed

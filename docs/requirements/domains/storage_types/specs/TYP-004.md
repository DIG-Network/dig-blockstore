## Summary

BlockRecord is an in-memory summary of a block's metadata, derived from L2BlockHeader. It is used for caching and chain management but is NOT persisted to RocksDB.

---

## Specification

```rust
use chia_protocol::Bytes32;
use dig_block::{L2BlockHeader, BlockStatus};

/// In-memory block metadata record derived from an L2BlockHeader.
/// Not persisted to RocksDB directly; reconstructed from headers on cache miss.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct BlockRecord {
    // Identity
    pub hash: Bytes32,
    pub height: u64,
    pub epoch: u64,
    pub parent_hash: Bytes32,

    // Chain position
    pub in_canonical_chain: bool,
    pub status: BlockStatus,

    // Statistics
    pub timestamp: u64,
    pub proposer_index: u32,
    pub spend_bundle_count: u32,
    pub total_cost: u64,
    pub total_fees: u64,
    pub additions_count: u32,
    pub removals_count: u32,
    pub block_size: u64,

    // L1 anchor
    pub l1_height: u32,
    pub l1_hash: Bytes32,

    // State
    pub state_root: Bytes32,
}

impl BlockRecord {
    /// Construct a BlockRecord from an L2BlockHeader and a BlockStatus.
    ///
    /// Extracts all relevant fields from the header. Fields not present
    /// in the header (e.g., block_size) are set to 0.
    pub fn from_header(header: &L2BlockHeader, status: BlockStatus) -> Self {
        Self {
            hash: header.hash(),
            height: header.height,
            epoch: header.epoch,
            parent_hash: header.parent_hash,
            in_canonical_chain: status == BlockStatus::Canonical,
            status,
            timestamp: header.timestamp,
            proposer_index: header.proposer_index,
            spend_bundle_count: header.spend_bundle_count,
            total_cost: header.total_cost,
            total_fees: header.total_fees,
            additions_count: header.additions_count,
            removals_count: header.removals_count,
            block_size: 0, // Not available from header alone
            l1_height: header.l1_height,
            l1_hash: header.l1_hash,
            state_root: header.state_root,
        }
    }
}
```

### Key Design Decisions

- **In-memory only:** BlockRecord is never serialized to RocksDB. It exists only in the block record cache (CAC-003) and is reconstructed from the header on cache miss.
- **block_size is 0 from header:** The header does not contain the full block size. The actual block_size can be updated after the full block is loaded, or left as 0 if only the header is available.
- **in_canonical_chain derived from status:** If `status == BlockStatus::Canonical`, then `in_canonical_chain` is true.

## Acceptance Criteria

- [ ] `BlockRecord` has all 18 fields as specified
- [ ] `BlockRecord` derives `Debug`, `Clone`, `PartialEq`, `Eq`
- [ ] `from_header()` correctly maps all header fields to record fields
- [ ] `from_header()` sets `hash` to the header's computed hash
- [ ] `from_header()` sets `in_canonical_chain` based on status
- [ ] `from_header()` sets `block_size` to 0
- [ ] `BlockRecord` is NOT serialized to any column family
- [ ] `BlockRecord` can be constructed and used without a RocksDB instance

---

## Implementation Notes

- Define in `src/types/block_record.rs`.
- The `hash()` method on `L2BlockHeader` comes from dig-block and uses chia-sha2 for hashing.
- `BlockStatus` is defined in dig-block (e.g., `Canonical`, `Pending`, `Orphan`).
- Future enhancement: add `with_block_size(size: u64)` builder method.

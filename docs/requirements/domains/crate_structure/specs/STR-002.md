## Summary

The module hierarchy MUST match the specification layout, providing a clear separation of concerns across store, config, types, constants, error handling, encoding, caching, canonical chain, compression, pipeline, and snapshot modules.

---

## Specification

The `src/` directory MUST contain the following module structure:

```
src/
  lib.rs                    # Crate root with re-exports
  store.rs                  # BlockStore struct and core implementation
  config.rs                 # BlockStoreConfig and configuration logic
  constants.rs              # CF_* and META_* constants
  cf_options.rs             # Per–column-family RocksDB options ([`TYP-003`](../../storage_types/specs/TYP-003.md))
  error.rs                  # BlockStoreError enum
  encoding.rs               # Key encoding functions
  compression.rs            # Zstd compression/decompression
  pipeline.rs               # Async write pipeline
  snapshot.rs               # Snapshot export/import
  types/
    mod.rs                  # Types module root
    block_record.rs         # BlockRecord struct
    stored_checkpoint.rs    # StoredCheckpoint struct
    chain_tip.rs            # ChainTip struct
    storage_stats.rs        # StorageStats struct
  cache/
    mod.rs                  # Cache module root
    sharded.rs              # Sharded LRU cache implementation
    warming.rs              # Cache warming on startup
  canonical/
    mod.rs                  # Canonical module root
    index.rs                # Canonical chain index logic
    mmap.rs                 # Memory-mapped canonical.bin file
```

Each `mod.rs` MUST declare its child modules. `lib.rs` MUST declare all top-level modules.

## Implementation Notes

- The module tree mirrors the SPEC Section 16 layout. Additional private helper modules may be added as needed, but the listed modules are required.
- Each subdirectory (`types/`, `cache/`, `canonical/`) requires a `mod.rs` that declares its submodules.
